# 虚表
实际代码只有一份，各类继承后通过虚代码表导向真正的实函数地址，类似系统陷阱


# 实际使用-virtual和override

> virtual：标记父类方法**允许子类重写**，这个方法会放进虚函数表，子类有机会替换虚表里的函数地址。 override：告诉编译器「我这个方法**专门用来重写父类的虚方法**」，会把子类虚表里对应条目换成当前这个函数地址。 如果不加`override`，只是写同名方法，**不会修改父类虚表，没有动态绑定，不会触发多态**。

以及还有abstract抽象方法，当父类没有实现，虚表对应位置为空，子类必须使用override实现填充虚表，否则子类不能实例化。
例子：System.Array数组必须override
# 
普通方法是**编译期绑定（静态绑定）**：编译时根据**变量的声明类型**直接确定调用哪个函数，不看堆上对象。 虚方法是**运行时绑定（动态绑定）**：运行时查对象虚表，才确定调用哪个函数，这就是多态的来源。
